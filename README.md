# Adhoc QA Agent for GitHub Copilot

An autonomous exploratory (adhoc) QA tester that runs inside **GitHub Copilot agent mode in VS Code**.
It drives a real Chromium browser through the **Playwright MCP server**. Coverage, the E2E flow, and
defects are logged to disk, and it produces a report with sections A–I (Markdown + HTML).

The full original rule set is kept in `qa/reference/MASTER_PROMPT.md`. Copilot loads only the
compact version (`.github/agents/adhoc-qa.agent.md`, about 75% shorter).

## What's inside

```
.github/agents/adhoc-qa.agent.md     the agent (rules, safety, token discipline, workflow)
.github/prompts/qa-start.prompt.md   /qa-start     → new run
.github/prompts/qa-continue.prompt.md /qa-continue → resume in a fresh chat
.github/prompts/qa-report.prompt.md  /qa-report    → finish + build report
.vscode/mcp.json                     Playwright MCP server (pinned 0.0.83), token-saving config
qa/qa.config.yaml                    app URL, roles, off-limits, approval keywords, timebox
qa/playwright-mcp.json               browser config: allowed origins, no images/snapshots in replies
qa/.env.qa.example                   test credentials template (copy to qa/.env.qa)
qa/ledger.py                         ledger CLI: coverage, flow, notes, defects, status, report
qa/reference/MASTER_PROMPT.md        full original prompt (reference only, not loaded)
```

## Requirements (on the machine that runs it)

- VS Code with GitHub Copilot and agent mode enabled (your org must allow MCP servers in Copilot).
- Node.js 18+ (for `npx @playwright/mcp`).
- Python 3.9+, then `pip install -r qa/requirements.txt` or `python3 -m pip install -r qa/requirements.txt`.
- **Google Chrome** installed normally. The agent drives a separate Chrome profile stored in
  `qa/.browser-profile`, so nothing needs to be downloaded. That matters behind corporate SSL
  proxies, which block Playwright's own browser download with `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`.

## Setup (5 minutes)

1. Copy this folder into the machine, either as its own workspace or merged into an existing repo root.
2. `pip install -r qa/requirements.txt`
3. Edit **`qa/qa.config.yaml`**: `base_url`, `production_hosts`, `purpose`, `primary_journey`, `roles`,
   `approval_required_keywords`, `off_limits`, `timebox_minutes`.
4. Edit **`qa/playwright-mcp.json`**: put production origins in `network.blockedOrigins`.
   `allowedOrigins` is empty (allow all) by default, because SSO logins such as Microsoft load from
   many domains. To lock it down, list the QA origin plus every API, CDN, and SSO origin.
   **Login:** `auth_hosts` and `login_mode` in `qa.config.yaml` cover single sign-on. In `auto` mode
   the agent types the secret names into the Microsoft pages. If MFA appears, it asks you to finish
   sign-in in the Chrome window and waits. The session is kept in `qa/.browser-profile`, so later
   runs usually skip login.
5. `copy qa\.env.qa.example qa\.env.qa` (Windows) or `cp qa/.env.qa.example qa/.env.qa`, then fill in
   test-account credentials. It's git-ignored.
6. Open the folder in VS Code → open `.vscode/mcp.json` → click **Start** on the `playwright` server.
7. Open Copilot Chat → pick the **Adhoc QA** agent → type **`/qa-start`**.

A Chromium window opens so you can watch. Set `"headless": true` in `qa/playwright-mcp.json` for
unattended runs.

## Running a session

| Step | Command | What happens |
|---|---|---|
| Start | `/qa-start` | Creates `qa/runs/run-YYYYMMDD-HHMMSS/`, logs in, maps the app, runs one E2E flow, then explores |
| Checkpoint | (agent tells you) | When the chat gets long it saves and asks you to open a **new chat** |
| Resume | `/qa-continue` in a new chat | Reloads the compact brief + status from disk and continues |
| Finish | `/qa-report` | Agent fills `narrative.yaml`, runs `ledger.py report` |

Output per run: `report.md`, `report.html`, `defects/D-###.yaml`, `evidence/*.png`, `ledger.json`.
You can check progress yourself anytime with `python qa/ledger.py status`.

## How it saves tokens

| Technique | Where |
|---|---|
| Compact agent rules (about 860 words vs about 3,700 in the master prompt) | `adhoc-qa.agent.md` |
| Browser actions return **no page snapshot** (`snapshot.mode: none`); agent verifies with cheap `browser_find` and snapshots only new pages | `playwright-mcp.json` + agent rules |
| **No images** sent to the model (`imageResponses: omit`); screenshots are saved to disk as evidence | `playwright-mcp.json` |
| Console limited to errors; network inspected with a URL filter only when needed | config + rules |
| Coverage, flow, defects live **on disk**, not in the chat; agent reads a 10-line `status` instead of files | `ledger.py` |
| Report sections, tables, and coverage percentages are generated by **Python**, not written by the model | `ledger.py report` |
| Session chunking: fresh chat every ~40 actions via `/qa-continue` keeps history short | `checkpoint_every_actions` |
| Restricted tool list (terminal, edit, read, todos, Playwright only) | agent `tools:` |

Tip: in the Copilot model picker, a smaller or faster model is usually enough for exploration. Switch
to a stronger model for `/qa-report` if you want sharper risk write-ups.

## Safety built in

- `ledger.py init` refuses to start if `base_url` is a production host or environment, or if the QA
  origin isn't in the browser's `allowedOrigins`.
- Browser requests to non-allowed origins are blocked by Playwright MCP. This is a guardrail, not a
  security boundary, and it doesn't apply to redirects.
- Credentials: the agent types only the secret **name** (e.g. `QA_USER_PASS`). Playwright MCP
  substitutes the value and redacts it in everything sent back to Copilot.
- Agent stops and asks before any control matching `approval_required_keywords`, and before
  irreversible, external, or bulk actions.
- The report generator enforces honesty rules:
  - It forces **NOT READY** if any open, confirmed Critical defect exists.
  - It downgrades **READY FOR REVIEW** when High defects, blocked items, or untouched items remain.
  - It flags confirmed defects that have no evidence.
  - It flags any "fixed" status that wasn't retested.
  - Every percentage states its denominator.

## Limits (what the report will state)

Browser-UI exploratory testing only. There's no database or server-log access, and API behavior is
only seen through browser network traffic. There's no load testing. Coverage is relative to what was
discovered.

## Troubleshooting

- **Agent opens the site, logs a few things, and stops:** it was blocked on login. Make sure
  `auth_hosts` is in `qa.config.yaml`. When it asks, finish the sign-in in Chrome and reply `done`.
  If Copilot asks "Continue?", click Continue. `.vscode/settings.json` raises that limit and
  auto-approves ledger commands. For Playwright tools, run **Chat: Manage Tool Approval** and tick
  the `playwright` server so each browser action doesn't need a click.
- **`UNABLE_TO_GET_ISSUER_CERT_LOCALLY`:** corporate SSL inspection. The config uses your installed
  Chrome (`"channel": "chrome"`), so no browser download is needed. If `npx` itself fails with the same
  error, point Node at your company's root certificate:
  `export NODE_EXTRA_CA_CERTS=/path/to/company-root-ca.pem` (ask IT for the file).

- **Agent can't run commands or edit files:** in the chat **Tools** picker, enable terminal/execute
  and edit tools for the Adhoc QA agent. Tool names can differ slightly between VS Code versions.
- **Playwright server fails to start:** check that `qa/.env.qa` exists and Node 18+ is on PATH.
  Run `npx -y @playwright/mcp@0.0.83 --help` to test.
- **Pages load blank or partially:** a needed API/CDN/SSO origin is missing from `allowedOrigins`.
- **PowerShell:** ledger values must use double quotes and no `$` (PowerShell expands it). The agent is
  told this, but watch for it if a command fails.
- **Corporate proxy:** add `"--proxy-server", "http://proxy:port"` to the args in `.vscode/mcp.json`.
